# Литклуб вуза

Telegram-бот и Mini App: читательский дневник, спрос на встречи по книгам и
конвейер их организации — от заявки ведущего до отметки о присутствии.

Задумка целиком, включая принятые на старте решения, — в
[docs/SPEC.md](docs/SPEC.md). Развёртывание — в [deploy/README.md](deploy/README.md).

## Три вкладки

**Книги** — поиск и список; на строке только «Читал» и «Хочу меро». Всё
остальное — на карточке книги: статус чтения, оценка, отзыв, выбор форматов
встречи. Отдельной вкладки дневника нет: то, что человек делает с книгой,
должно лежать рядом с книгой.

**Афиша** — один список из двух ярусов. Наверху встречи (голосующиеся
подсвечены — по ним ждут действия), под ними спрос: книги, которых ждут, но
ведущего ещё нет. Это одна история на разных стадиях.

**Профиль** — анкета целиком редактируемая, «Мои книги», друзья, свои заявки и
встречи, вход в админку.

## Запуск

Нужны Python 3.12, Node 20+ и Postgres 16. **Все команды — из корня репозитория.**

Зависимости:

```bash
cd backend && python3 -m venv venv && ./venv/bin/pip install -r requirements-dev.txt && cd ..
```

База — либо `docker compose up -d`, либо локальный Postgres; оба варианта
слушают 5433, поэтому `DATABASE_URL` одинаков. На машине, где это писалось,
поднят второй вариант: `brew services start postgresql@16`, роль и база
`litclub`, плюс расширение `pg_trgm`.

Конфигурация:

```bash
cp .env.example .env
```

Заполнить `TELEGRAM_BOT_TOKEN`, `SECRET_KEY`, `BOOTSTRAP_SUPERADMIN_TG_ID`.

Миграции:

```bash
cd backend && ./venv/bin/alembic upgrade head && cd ..
```

Сервер API:

```bash
cd backend && ./venv/bin/uvicorn app.main:app --port 8010 --reload --reload-include ../.env
```

`--reload-include ../.env` обязателен: uvicorn следит только за `.py`, а
конфигурация читается один раз при старте — без флага правка токена не
подхватится, и приложение будет уверять, что токен не задан.

Mini App (отдельная вкладка терминала):

```bash
cd miniapp && npm install && npm run dev
```

Vite проксирует `/api` на бэкенд, поэтому наружу торчит один порт — 5183.

Порты выбраны свои — 8010 и 5183: на этой машине рядом крутится киноклуб,
он занимает 8000 и 5173. У Vite стоит `strictPort`, поэтому занятый порт
теперь честная ошибка, а не тихий переезд на соседний (иначе туннель
однажды посветит наружу чужим проектом — так и случилось при первой проверке).

Бот (третья вкладка):

```bash
cd backend && ./venv/bin/python -m app.bot
```

### HTTPS-туннель

Telegram не принимает `localhost` и `http`. В разработке:

```bash
scripts/tunnel.sh
```

Скрипт поднимает туннель, вписывает адрес в `.env` и переподключается, когда
бесплатный лимит истекает. Бот следит за `.env` и сам переставляет кнопку меню
— BotFather при каждом перезапуске трогать не нужно.

## Что настроить у бота

1. **Выключить privacy mode** — @BotFather → `/mybots` → Bot Settings → Group
   Privacy → Turn off. Без этого бот не увидит сообщения в переговорках и не
   сможет вычистить чат перед следующим кандидатом.
2. **Завести пул переговорок.** Бот не умеет создавать чаты: в Bot API нет
   такого метода, и добавлять людей в чат он тоже не может. Создайте руками
   несколько пустых супергрупп, сделайте бота администратором с правами
   «изменение профиля группы», «приглашение пользователей» и «удаление
   сообщений», и добавьте их в админке по `chat_id` (узнать id: переслать
   сообщение из группы боту @userinfobot).
3. **Ключ Google Books** — не обязателен, но на общих IP анонимная квота
   выбирается быстро и источник начинает отвечать `429`. Поиск это переживает
   (остаётся Open Library, а в интерфейсе появляется сноска), но с ключом
   выдача заметно полнее: https://console.cloud.google.com/apis/library/books.googleapis.com

## Проверка

```bash
cd backend && ./venv/bin/pytest && ./venv/bin/ruff check app
```

```bash
cd miniapp && npm test && npx tsc -b && npx oxlint
```

Тесты бэкенда идут в отдельной базе `litclub_test` — она создаётся сама.
