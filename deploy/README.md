# Развёртывание

Адрес сервера и имя пользователя в этом файле заменены на `СЕРВЕР` намеренно:
репозиторий публичный, а на хосте включён вход по паролю. Настоящие значения —
в приватных заметках клуба; подставляйте их вместо плейсхолдера.

Домен: **culc-bot.cu3rd.ru**. TLS терминирует Caddy на хосте, сертификат
Let's Encrypt выпущен и действует до 8 декабря 2026, `http://` отдаёт 308 на
`https://`. Caddy проксирует на `127.0.0.1:8090`, туда же публикует порт
контейнер `api`.

```
culc-bot.cu3rd.ru ──TLS──> Caddy ──> 127.0.0.1:8090 ──> контейнер api :8000
```

`X-Forwarded-For` и `X-Real-IP` Caddy проставляет сам, WebSocket проксирует из
коробки — приложению дописывать ничего не нужно. Uvicorn запускается с
`--proxy-headers --forwarded-allow-ips '*'`, потому что видит только Caddy.

## Порт публикуем только на localhost

В `docker-compose.prod.yml` стоит `"127.0.0.1:8090:8000"`, и это не украшение.
Без явного адреса Docker публикует порт на всех интерфейсах и правит iptables
в обход ufw: приложение оказалось бы доступно снаружи по голому http, мимо
Caddy и мимо TLS. Так же сделаны все остальные сервисы на этом хосте.

Занятые порты хоста — не пересекаться: 8000, 8089 (cinema), 8090 (мы),
8100–8102, 8201, 5432, 2019 (admin API Caddy). Если понадобится второй порт —
свободен 8091.

## Секреты

`.env` в образ не попадает: он перечислен в `.dockerignore`, а в контейнер
значения приходят через `env_file`. Каталог, который приложение отдаёт наружу
как статику, — только `/app/frontend`, и в нём лежит исключительно результат
сборки Vite.

Это не теория: через пару минут после появления домена в CT-логах на него
пришёл сканер (104.244.74.39) и перебирал `/.env`, `/.env.prod`, `/.env.local`.
Тогда отвечал 502, ничего не утекло. После запуска эти пути отдаст SPA-фолбэк
из `app/main.py` — он умеет отдавать только файлы внутри `FRONTEND_DIR` и
проверяет, что вычисленный путь лежит внутри него, так что выйти за пределы
каталога запросом нельзя.

Проверить после первого запуска:

```bash
curl -s -o /dev/null -w '%{http_code}\n' https://culc-bot.cu3rd.ru/.env
```

Ожидаемо — 200 с содержимым `index.html` (SPA-фолбэк), но никогда с
содержимым `.env`. Если однажды увидите там переменные окружения — значит
`.env` попал внутрь `FRONTEND_DIR`, и это авария.

## Обновление

Одной командой с рабочей машины:

```bash
deploy/release.sh kir@СЕРВЕР
```

Скрипт заливает код, пересобирает контейнеры и проверяет, что сайт поднялся и
отдаёт свежий бандл. Запускать должен человек: docker на сервере требует sudo
с паролем.

Отдельный шаг пересборки легко потерять — тогда сервер продолжает отдавать
старый образ, и по коду на диске это незаметно. Проверить, что живёт снаружи:

```bash
curl -s https://culc-bot.cu3rd.ru/ | grep -oE '/assets/index-[^"]+\.js'
```

Хеш должен совпадать с тем, что лежит в `miniapp/dist/assets/` после
локальной сборки.

## Первый запуск

С рабочей машины:

```bash
deploy/sync.sh kir@СЕРВЕР
```

Дальше на сервере, в `~/lit-club`:

```bash
cp .env.example .env
```

и заполнить: `TELEGRAM_BOT_TOKEN`, `GOOGLE_BOOKS_API_KEY`,
`BOOTSTRAP_SUPERADMIN_TG_ID`, `SECRET_KEY` (`openssl rand -hex 32`),
`POSTGRES_PASSWORD` (тоже случайный) и, главное,

```
MINIAPP_URL=https://culc-bot.cu3rd.ru
```

Этот адрес бот ставит кнопкой меню, и по нему же Telegram открывает Mini App.
`DATABASE_URL` из `.env` не нужен — его задаёт compose, база живёт в соседнем
контейнере.

```bash
sudo docker compose -f docker-compose.prod.yml up -d --build
```

## Один токен — один бот

Long polling у Telegram эксклюзивен: два процесса с одним токеном отбирают
обновления друг у друга, и оба ведут себя странно (в логе — `Conflict:
terminated by other getUpdates request`). Поэтому **перед запуском на сервере
нужно остановить локального бота** на ноутбуке:

```bash
pkill -f "app.bot"
```

Локальный API и Vite при этом можно оставить: они боту не мешают. А вот
`scripts/tunnel.sh` лучше тоже остановить — он переписывает `MINIAPP_URL`
в локальном `.env`, но на сервер тот `.env` не уезжает (`sync.sh` его
исключает), так что боевой адрес он не собьёт.

## Обновление

```bash
deploy/sync.sh kir@СЕРВЕР
ssh kir@СЕРВЕР 'cd ~/lit-club && sudo docker compose -f docker-compose.prod.yml up -d --build'
```

Бэкап конфига Caddy на хосте: `/etc/caddy/Caddyfile.bak.2026-09-09-150235`.
